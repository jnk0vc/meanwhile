# Meanwhile — Claude Mod 設計

Oct 6, 2026 · @Hayato Konya

## 概要

Meanwhile は、Claude Code が作業している間だけ、同じく待っている誰かと匿名で1対1チャットできる Mod。言語が違えば Haiku が自動で翻訳し、自分の Claude の作業が終わったら相手に「最後の一言」を1回だけ送って退室する。

**ゴール**

- 待ち時間に、知らない誰かとアイディアを相談し合える
- 言語の壁をなくす（翻訳は自動、原文も見られる）
- 作業の邪魔をしない：Claude が終わったら会話も終わる

**非ゴール**

- フレンド登録や継続的な関係づくり
- グループチャット
- 作業内容の自動共有（プロンプト、コード、ツール出力は送らない。相談したいことは自分の言葉で書く）
- Claude Code 以外の環境での利用

## ユーザー体験フロー

プロンプト送信から一定時間たっても Claude が作業中なら相手を探し、終わったら最後の一言で別れる。短いタスクでは何も起きない。

1. **作業開始**：プロンプトを送ると Mod が「作業中」に入る。30秒（設定可）たってもまだ作業中ならマッチング待ちへ。
2. **マッチ**：待機中の相手が見つかるとサイドパネルが開き、「Someone とつながりました」と相手の言語を表示。話題は事前に決めず、つながってからフリートーク。
3. **チャット**：相手の言語が違えば翻訳文を大きく、原文を小さく併記。
4. **自分の作業完了**：入力欄が「最後の一言」モードに切り替わる（60秒以内に1通）。送信かスキップで退室。
5. **相手が先に完了**：相手の最後の一言が届き、「Someone は作業に戻りました」と表示。自分がまだ作業中なら、次の相手を探しに戻る。
6. **終了**：会話ログは退室と同時に消える（ローカルにも残さないのが既定）。

Claude が途中で許可や質問への回答を求めたときは、パネル上部にバナーを出して見逃しを防ぐ。チャットはそのまま続けられる。

## システム構成

構成は、引き合わせるだけのマッチングサーバーと、当人どうしの直接通信（WebRTC）。翻訳は各ユーザー自身の Claude Code でヘッドレス Haiku が行う。サーバーは本文に触れず1ペアにつき数リクエストしか使わないので、利用者が増えても負荷は小さい。

&#91;embedded content: システム構成 · サーバーで引き合わせ、WebRTC で会話、翻訳は各自\]

**通信方式：WebRTC**

- pure TypeScript 実装（werift など）の DataChannel を使い、ネイティブモジュールに頼らない。
- マッチングサーバーは Cloudflare Worker + Durable Objects。キューに並んだ2人を組ませ、その2人の間でだけ接続情報（SDP / ICE）を受け渡す。本文は通らない。
- STUN は公開サーバーを使い、TURN は置かない。直接つながらなければ「つながりませんでした」と表示して次の相手を探す。
- 待機者の一覧はどこにも公開しない。相手の IP が分かるのはマッチした2人の間だけ。

**検証すること**

- [ ] werift の DataChannel が Claude Code の Mod 環境で動くか
- [ ] Mod からヘッドレスの Claude Code を起動して Haiku を呼べるか、その応答速度
- [ ] TURN なしでの接続成功率

## 状態遷移とマッチングルール

状態は5つ。作業時間の差は「相手が先に終わったら自分はマッチ待ちに戻る」で吸収する。

&#91;embedded content: 状態遷移 · 5状態\]

- 30秒未満で終わるタスクではマッチングしない。
- キューは言語を混ぜた FIFO の1本。翻訳があるので言語で分けない。
- 同じセッション内では、直前の相手と再マッチしない。
- 相手が先に退室したら、相手の最後の一言を表示してから自動でマッチ待ちへ戻る。
- マッチ待ち中に作業が終わったら、何も出さずに待機へ。
- Claude が入力待ちになっても状態は変えず、パネルにバナーだけ出す。

## メッセージプロトコル

マッチングサーバーとは WebSocket で接続情報だけを、相手とは WebRTC DataChannel で会話をやりとりする。会話で送るのは常に原文で、翻訳は受信側が行う。

**マッチングサーバーとの通信**

| 方向 | type | ペイロード | 用途 |
| --- | --- | --- | --- |
| C → S | `queue.join` / `queue.leave` | `pubkey` | マッチング待ちの開始・取消 |
| S → C | `match.found` | `roomId`, `role`（`offer` / `answer`） | ペア成立と、どちらが接続を始めるか |
| C ↔ S ↔ C | `signal` | `sdp` または `ice` | ペアの間だけで接続情報を受け渡す |
| C → S | `report` | `roomId`, `reason` | 相手を通報 |
| S → C | `notice` | `code` | 締め出し中、レート制限など |

**相手との通信（DataChannel）**

| type | ペイロード | 用途 |
| --- | --- | --- |
| `hello` | `v`（プロトコル版）, `lang` | 接続直後に互いに送る |
| `chat` | `text`（最大200文字） | 通常メッセージ（原文） |
| `final` | `text` または `null`（スキップ） | 最後の一言。送信後に切断 |
| `bye` | `reason`（`done` / `blocked`） | 退室 |
| `ping` | なし | 15秒ごとの生存確認 |

DataChannel がつながったらマッチングサーバーとの WebSocket は閉じる。10秒で接続できなければ失敗として次の相手を探し、45秒 `ping` が途絶えたら相手が退室したものとして扱う。

## 翻訳設計

翻訳は受信側の Mod が、受信者自身の Claude Code をヘッドレスで起動して Haiku に頼む。費用は受信者の契約の利用枠に乗り、本文は運営に一切届かない。

- **言語の決め方**：`hello` で互いの言語（OS のロケール、設定で上書き可）を交換する。
- **出力形式**：`{"translated": "…", "flagged": false}` の JSON のみ。翻訳文は口調、絵文字、スラングを保つ。
- **インジェクション対策**：相手の本文は「翻訳対象のデータ」としてタグで囲み、中の指示には従わせない。ヘッドレス Claude Code はツールを一切使えない設定で起動する（相手の文でコマンドを実行させない）。MCP も読み込まず、空の一時ディレクトリで起動して、プロジェクトの CLAUDE.md などを読ませない。
- **失敗時**：5秒でタイムアウトしたら原文だけ表示し、「翻訳できませんでした」と添える。

**同じ言語どうしは Haiku を一切呼ばない。** その場合のチェックは、受信側のローカル NG ワードフィルタとブロックだけになる。

## 安全・プライバシー

見知らぬ人との匿名チャットなので、作業内容を絶対に漏らさないことと、嫌な相手からすぐ離れられることを最優先にする。

**作業内容を漏らさない**

- 送るのはパネルの入力欄のテキストだけ。プロンプト、ツール出力、ファイルパス、リポジトリ名には Mod のコード上で触れない。
- 送信前にローカルで API キー、トークン、メールアドレスらしき文字列を検出したら警告して止める。
- Mod はオープンソースで公開し、通信先がマッチングサーバーと会話相手だけだと確認できるようにする。

* 相談内容は見知らぬ人に届く。パネル上部に「アイディアは匿名の相手に共有されます」と常に表示し、未公開のアイディアを書くかどうかは本人に任せる。

**受信側で守る**

攻撃者は Mod を使わず自作クライアントでも来られるので、守りはすべて受信側の Mod に置く。相手は「ターミナルを開いている開発者」を狙えるので、特にコマンドを使った詐欺を警戒する。

- 受信文は純粋なテキストとして扱い、制御文字、ANSI エスケープ、ゼロ幅文字、文字の向きを変える制御文字を除去する。
- `curl … | sh`、`npm install`、Base64 の塊など、コマンドらしい文には警告ラベルを付け、コピーボタンは出さない。
- URL はリンクにせず、プレーンテキストで表示する。
- 相手の文を Claude 本体の文脈には絶対に流さない。
- 受信メッセージはスキーマ検証とサイズ上限を通し、未知の `type` は捨てる。
- 依存ライブラリは最小限にしてバージョンを固定し、自動更新しない。

**嫌な相手から離れる・荒らし対策**

- 表示名は全員「Someone」。
- 受信側の Haiku が `flagged` と判定したメッセージは伏せて表示する（同じ言語どうしはローカル NG ワード）。
- 各メッセージに送信者の鍵で署名し、受信側は署名つきでメモリに保持する。通報時はそれを添付し、サーバーが署名を検証することで捏造や虚偽通報を防ぐ。
- 通報・ブロックはワンクリックで即切断。ブロックは手元で即時に効き、検証できた通報が重なった鍵や IP は一定時間マッチング対象から外す。通報ログは判定後に削除する。
- ボットや鍵の作り直しはクライアントでは止められないので、マッチングサーバーに `queue.join` への軽い proof-of-work と IP ごとのレート制限だけ置く。
- **相手に IP アドレスが見える。** 初めて有効にするときに明示して同意を取る。

**運用**

- 既定はオフ。ユーザーが明示的に有効にしたときだけ動く。
- 運営が本文を受け取るのは通報に添えられた発言だけで、署名を検証したら捨てる。会話ログは各自の手元にも残さないのが既定。
- Team / Enterprise では管理者が Mod の読み込みを制限できるので、組織環境では使えない前提で考える。
- TURN を置かないので、UDP が塞がれた環境ではつながらない。
- 利用規約で18歳以上に限定する。

## 設定・MVP・未決事項

MVP はマッチング、1対1チャット、翻訳、最後の一言、通報の5つに絞る。

**設定項目**

| 設定 | 既定値 | 選択肢 |
| --- | --- | --- |
| 有効化 | オフ | オン / オフ |
| マッチ開始までの待ち時間 | 30秒 | 15〜120秒 |
| 自分の言語 | OS のロケール | 任意の言語 |
| 翻訳の表示 | 翻訳＋原文 | 翻訳のみ / 翻訳＋原文 / 原文のみ |
| 最後の一言の制限時間 | 60秒 | 30〜180秒 |
| 通知音 | オフ | オン / オフ |

**MVP の後に足すもの**

- 同じ言語の相手を優先するオプション
- 興味タグ（「Rust書いてる」など）でゆるく相手を選ぶ
- 絵文字リアクション

* 退室時に、相談の要点を Haiku で自分用メモにまとめて手元に保存（任意）

**未決事項**

- [ ] Claude が入力待ちのとき、マッチング待ちを止めるか続けるか
- [ ] Mods の具体的なイベント名と UI API（実装前に公式ドキュメントで確認）

* [ ] 同じ言語どうしのモデレーションを NG ワードだけで足りるとするか

- [ ] 相手が人間であることをどこまで担保するか（Mod 経由の接続のみ受け付ける、レート制限など）

* [ ] ブロック用に鍵をインストールごとに固定するか、毎回変えるか（匿名性とのトレードオフ）

- [x] 通報時に運営が署名つきログ（本文）を受け取ることの扱い → 署名の検証にだけ使い、検証したら捨てて保存しない。運営が受け取るもの・使い道・残す期間は、READMEの「運営が受け取るもの」に載せる
